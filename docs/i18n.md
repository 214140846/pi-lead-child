# 界面的多语言

本文说明界面文字怎样支持多种语言，以及怎样把写死的中文迁到这套机制里。第一期支持英文和中文，缺省是英文（用户 2026-11-01 定）。

## 语言从哪里来

界面语言是外观偏好的一个字段：`locale`，取值 `en` 或 `zh`。

- 用户在设置 → 外观的「语言」一行里选。选了立即保存，不等表单的「保存」。
- Lead 用 `update_design_preferences` 的 `locale` 参数改。权限和外观的其他字段一样。
- daemon 把它存在 `kv` 的 `ui.design-preferences` 里。没有存过时按 `en` 算。
- 网页把上次的语言记在 `localStorage`（`apps/companion/src/i18n/localeCache.ts`）。连上 daemon 以前，界面按记住的语言画。

## 写法

文案写成有类型的目录，不用字符串键。机制在 `packages/protocol/src/i18n.ts`。

```ts
// apps/companion/src/features/settings/appearance.messages.ts
import { defineMessages } from '@/i18n';

export const appearanceMessages = defineMessages({
  en: {
    save: 'Save',
    updated: (when: string, who: string) => `Last changed: ${when}, ${who}.`,
  },
  zh: {
    save: '保存',
    updated: (when, who) => `最近一次修改：${when}，${who}。`,
  },
});
```

规则：

1. 目录放在用它的文件旁边，文件名是 `<区域>.messages.ts`。
2. 先写 `en`，再写 `zh`。`zh` 必须有和 `en` 完全一样的键和参数。漏写、多写或者参数不对，typecheck 会报错。
3. 带参数的文案写成函数：名字、数量、时间都从参数进来。不要在调用处拼接句子，因为两种语言的语序不一样。
4. 英文的单复数在函数里处理，例如 `(n) => (n === 1 ? '1 ticket' : \`${n} tickets\`)`。
5. 语言的名字不翻译。每种语言用它自己的文字写（`LOCALE_NAMES`）。
6. 英文文案按 STE（ASD-STE100）写：句子短，用主动语态，一个词只表示一个意思。

## 在哪里取文案

| 位置 | 怎么取 |
|---|---|
| companion 的组件 | `const m = useMessages(appearanceMessages)`（`@/i18n`） |
| companion 的纯函数（`*Model.ts`） | 收一个 `locale: Locale` 参数，在函数里取 `appearanceMessages(locale)` |
| 组件库 `packages/components` | `useLocale()`。组件库不依赖 protocol，目录要自己定义同样的形状 |
| daemon、engine、gateway | 用 store 的 `getLocale(db)` 取用户现在的语言，再取目录 |

日期和时间用 `intlLocale(locale)` 交给 `Intl.DateTimeFormat`。两种语言都用 24 小时制（设计规范 P14.2）。

## 哪些文字要迁

迁的是用户在界面上看到的文字：

- 按钮、标题、说明、占位符、无障碍标签。
- 状态、错误和提示的句子。
- daemon 生成、界面直接显示的文字，例如主人操作的摘要、给设置页的错误。

这些文字先不迁：

- 注释。
- 给模型看的文字：Lead 的系统提示词、skill、工具说明、只返回给 Lead 的错误。Lead 从 appearance 一节知道界面语言，用用户这条消息的语言回复。
- 测试里的样例数据。

daemon 写进数据库的文字按写入时的语言写。用户以后换语言，旧记录不重写。

## 迁一个文件的步骤

1. 在文件旁边新建或补充 `*.messages.ts`，把文件里的中文字面量移进去，写好英文。
2. 把文件里的字面量换成 `m.<键>`。纯函数加 `locale` 参数。
3. 更新这个文件的测试。缺省语言是英文，所以断言改成英文；要测中文时，显式传 `'zh'`，或者把外观偏好设成 `zh`。
4. 运行 `apps/companion/src/i18nBoundary.test.ts`。它扫描整个 `src`，代码里有中文字面量时失败（注释、测试和 `*.messages.ts` 除外）。认 daemon 写的中文原文的文件在它的例外清单里。
5. 运行 `npm run typecheck:companion` 和这个区域的测试。
